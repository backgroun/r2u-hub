# R2U 허브 이전 계획서 (Upstash → Supabase, Vercel → 회사 팀)

작성일: 2026-10-17 · 상태: **계획 (미실행)** · 실행 시작: 사용량 초기화 이후

> 이 문서는 실행 전에 합의하려는 계획이다. 실행 중에는 8장의 점검표를 그대로 따라간다.
> 접속 주소·키·비밀번호는 이 문서와 채팅에 쓰지 않는다. Vercel 환경변수에만 둔다.

---

## 1. 목표와 원칙

1. **크루원이 불편을 느끼지 않는다.** 대회 주간·당일에는 건드리지 않는다. 전환은 평일 새벽, 점검 15~30분 안에 끝낸다.
2. **언제든 되돌릴 수 있다.** 전환 후 2주 동안 Upstash 데이터를 그대로 둔다. 접속 설정 하나(`DATA_BACKEND`)로 되돌린다.
3. **한 번에 한 가지만 바꾼다.** ① DB(Supabase) → 안정 확인 → ② 호스팅(Vercel). 두 가지를 같은 날 바꾸지 않는다.
4. **연습을 먼저 한다.** 운영 데이터를 읽기만 해서 복사본으로 리허설한 뒤, 같은 절차로 실제 전환한다.
5. **검증은 숫자와 화면 둘 다.** 키 개수·값 비교(자동) + 화면 점검표(수동).

## 2. 현황 (읽기 전용 조사 결과, 2026-10-17)

### 데이터
- 키 **194개**, 용량 약 **700KB**. 이전 자체는 작고 빠르다.
- 키 종류(접두어 `r2u:`): 회원(`members` 해시), 포인트(`pt:<닉>` 약 32), 대회(`races` 해시, `race:<id>:p|cheer|after`), 뒷풀이·단사·카풀 참석(`after:<id>` 등), 월간 기록(`month:YYYY-MM`), 대회 기록(`racerec:<닉>`), 스팟게임(`gear:*`), 공지·푸시 구독(`notices`, `push`), 이벤트 빙고(`bingo:*`, `event` 관련), 가입 요청(`joinreq`), 달리기 기록(`runs:<닉>`). 공구(`gb:*`)는 같은 DB에 있다.
- 값의 형태: 문자열, 해시, 정렬 집합(zset), 리스트. 일부는 만료 시간이 있다(단사 사진, 1시간 알림 제한 표식, 로그인 실패 횟수, 접속 간격 제한).

### 코드
- Redis 클라이언트가 **3곳**에 따로 있다: `src/lib/hub.ts`(허브 전체), `src/lib/db.ts`(공구), `src/lib/event.ts`(이벤트 숨김 등). 셋 다 같은 DB를 본다.
- 쓰는 명령 약 25종: `get set(nx, ex) mget del exists incr expire expireat keys hset hsetnx hget hmget hdel hexists hkeys hgetall hincrbyfloat zadd zrem zrange(byScore, rev) lpush ltrim lrange` + `pipeline`, `multi`.
- Upstash 클라이언트는 값을 **자동으로 JSON 변환**한다(객체 저장, 읽을 때 복원, 숫자·문자열 구분). 어댑터가 이 규칙을 똑같이 재현해야 한다. (가장 큰 위험 요소)

### 환경변수 (이름만)
`SESSION_SECRET` `STAFF_PASSWORD` `ADMIN_PASSWORD` `CRON_SECRET` `VAPID_PUBLIC_KEY` `VAPID_PRIVATE_KEY` `VAPID_SUBJECT` `NEXT_PUBLIC_VAPID_PUBLIC_KEY` `NEXT_PUBLIC_SITE_URL` `SHEET_WEBHOOK_URL` `SHEET_WEBHOOK_SECRET` `NAVER_CLIENT_ID/SECRET` `KAKAO_REST_API_KEY` `COUPANG_ACCESS_KEY/SECRET_KEY` + DB 접속(`KV_REST_API_*` / `UPSTASH_REDIS_REST_*` → 이전 후 `DATABASE_URL`).

### 외부 연결
- GitHub Actions `collect-news`가 2시간마다 `APP_URL/api/cron/collect-news` 호출(`APP_URL`, `CRON_SECRET` 시크릿).
- 푸시 알림(웹 푸시)은 **주소(origin)에 묶인 구독**이다. 주소가 바뀌면 전원 재구독.
- 홈 화면 앱(PWA, `sw.js`)도 주소에 묶인다.
- 구글 시트 웹훅(회원 동기화).

## 3. 전체 일정

실제 날짜는 **사용량 초기화일**과 **대회 일정**으로 정한다. 대회 주간(대회 전 2일~당일)은 피한다.

| 단계 | 내용 | 운영 영향 | 소요 |
|---|---|---|---|
| P0 사전 준비 | 접속 주소 설정, 백업 파일 만들기, 점검표 확정 | 없음 | 0.5일 |
| P1 개발 | Postgres 어댑터, 이전 스크립트, 점검 모드(쓰기 차단), 테스트 | 없음 (배포 안 함) | 1~2일 |
| P2 리허설 | 운영 데이터를 **읽기만** 해 복사본 DB로 이전, 화면 비교 | 거의 없음 (읽기 몇백 건) | 0.5일 |
| P3 전환 | 평일 새벽 점검 15~30분, 접속 설정 변경 | 점검 안내 필요 | 1회 |
| P4 관찰 | 3~7일 로그·속도·오류 관찰 | 없음 | 1주 |
| P5 Vercel 리허설 | 회사 팀에 **새 프로젝트로 복제 배포**해 다른 주소로 시험 | 없음 | 0.5일 |
| P6 Vercel 전환 | 프로젝트 이전 또는 주소 교체, 푸시·앱 영향 점검 | 짧은 점검 | 1회 |
| P7 정리 | Upstash 2주 보관 후 해지, 임시 파일 삭제 | 없음 | — |

권장 간격: P3 → P4(1주) → P5~P6 → 2주 뒤 P7.

## 4. 기술 설계

### 4-1. 어댑터 방식 (앱 코드를 거의 안 바꾼다)
- 앱이 쓰는 Redis 명령 25종을 **같은 모양의 함수로 Postgres 위에서 제공**한다. `hub.ts`·`db.ts`·`event.ts`의 `redis` 객체만 교체한다.
- 환경변수 `DATA_BACKEND=redis|postgres`로 선택한다. 기본값은 `redis`(지금과 동일). 전환·롤백은 이 값 하나로 한다.
- 표 하나로 충분하다(데이터 700KB):

```
kv (
  key        text    not null,
  type       text    not null,   -- 's' 문자열 / 'h' 해시 / 'z' 정렬집합 / 'l' 리스트
  field      text    not null default '',  -- 해시 필드, 정렬집합 멤버, 리스트 인덱스
  value      text,               -- 직렬화한 값
  score      double precision,   -- 정렬집합용
  expires_at timestamptz,        -- 없으면 영구
  primary key (key, field)
)
index on (key), index on (expires_at) where expires_at is not null
```
- 만료: 읽을 때 `expires_at < now()`를 걸러내고, 주기적으로(요청 중 가끔) 지운다.
- 파이프라인·`multi`: 한 번의 왕복으로 묶어 실행하고, `multi`는 트랜잭션으로 처리한다.
- 값 직렬화 규칙: Upstash 클라이언트와 동일하게 재현한다(객체→JSON 문자열, 읽을 때 JSON으로 보이면 복원, 숫자는 숫자로). **이 규칙은 단위 테스트로 못박는다.**

### 4-2. 연결
- Supabase **Transaction pooler** 주소(포트 6543)를 쓴다. 함수 하나당 연결 수는 1~2개로 제한.
- Data API(공개 REST)는 **끈 상태**를 유지한다. 서버만 직접 접속한다. `service_role` 키는 쓰지 않는다.
- Vercel 함수 지역을 DB 지역(서울)과 가깝게 맞춘다(기본은 미국 동부일 수 있음 → 느려짐). 전환 전에 지역 설정을 확인한다.

### 4-3. 이미 해 둔 요청 절감 (전환과 별개로 유효)
- 대회 목록 캐시(15분, 변경 시 즉시 무효화), 공구 자동 새로고침 완화, 데이터 장애 안내 화면. (Upstash 요청 수를 크게 줄이는 변경 → 배포 필요)

### 4-4. 점검 모드 (쓰기 차단)
- 전환 새벽에 **쓰기 요청만 막고 읽기는 허용**하는 스위치(환경변수 `MAINTENANCE=1`)를 둔다. 마지막 복사 중 새 기록이 생기는 것을 막는다.
- 화면 위쪽에 "새벽 점검 중, 잠시 후 이용해 주세요" 배너.

## 5. 검증 방법

### 자동
1. **어댑터 단위 테스트**: 25개 명령 각각 + 직렬화 규칙(숫자/문자열/객체/null/빈 문자열/한글 키) + 만료 + `nx`.
2. **두 백엔드 비교 테스트**: 같은 시나리오를 Redis 가짜 서버와 Postgres에 실행해 결과가 같은지 비교.
3. **이전 검증 스크립트**: 키 개수, 종류별 개수, 해시 필드 수, 정렬집합 멤버 수, **모든 값의 해시값 비교**.

### 수동 (8장 점검표)
대표 화면을 두 곳(Upstash / Supabase)에서 열어 눈으로 비교한다.

## 7. 롤백 계획

- **기준**: 점검표 실패, 값 불일치, 응답 시간 3초 초과가 반복, 오류율 급증 중 하나.
- **전환 직후(쓰기 차단 중)**: `DATA_BACKEND=redis`로 되돌려 재배포. Upstash는 손대지 않았으므로 즉시 원상 복구.
- **전환 후 쓰기가 생긴 뒤**: Postgres에서 바뀐 것만 **역복사 스크립트**로 Upstash에 되돌린 뒤 설정을 바꾼다. 가능하면 전환 후 3시간 이내에 판단한다.
- 롤백 후에는 원인을 고치고 리허설부터 다시 한다.
- Upstash 데이터는 전환 후 **2주 동안 삭제하지 않는다.**

## 9. Vercel 이전 계획 (P5~P6)

### 사전 조건
- Supabase 전환 후 **최소 3~7일 안정** 확인.
- Upstash(마켓플레이스) 연결을 프로젝트에서 분리(이전을 막을 수 있음).
- 회사 팀 권한(프로젝트 이전 가능한 역할), 결제 수단 확인.

### 핵심 위험: 주소와 푸시
- 현재 주소 `crew-groupbuy.vercel.app`. 크루원은 이 주소로 홈 화면 앱·푸시 구독을 만들었다.
- **주소가 바뀌면 전원이 앱 재설치·푸시 재구독이 필요하다.** 그래서 옮긴 뒤에도 같은 주소가 유지되는지를 **리허설에서 먼저** 확인한다.
- 불안하면 내 도메인을 붙이고, 도메인을 기준으로 이전한다(도메인 비용은 별도 결정).

### 방식 선택
1. **프로젝트 이전(Transfer)**: 설정·환경변수·배포 이력이 함께 간다. 주소 유지 가능성이 높지만 보장은 아니다 → 리허설 불가(실행 즉시 이전).
2. **새 프로젝트 복제 + 주소 교체**: 회사 팀에 새 프로젝트를 만들어 다른 주소로 먼저 검증한 뒤, 도메인(또는 별칭)을 옮긴다. 안전하지만 주소 유지를 위해 사용자 도메인이 필요할 수 있다.
- **권장**: 가능하면 (2)로 리허설 후, 주소 유지가 확인되면 (1) 또는 (2)로 확정.

### 환경변수 이관 목록
2장의 변수 전부. 특히 **`SESSION_SECRET`은 바뀌면 전원 로그아웃**, **`VAPID_*`는 바뀌면 푸시 구독이 무효**가 되므로 값 그대로 옮긴다.

### 추가 점검
- GitHub 저장소 연결을 회사 팀에서 다시 연결(권한 필요).
- **배포 보호(Vercel Authentication)** 설정이 production을 가리지 않는지 — 크루원이 로그인 없이 열려야 한다.
- GitHub Actions 시크릿 `APP_URL`, `CRON_SECRET` 갱신.
- 이 작업 폴더의 Vercel 연결 정보(프로젝트 ID)와 배포 명령의 팀 이름 갱신.
- 분석·로그 이력은 옮겨지지 않을 수 있음.

| 접속 주소(DB) 유출 | 낮 | 높음 | 환경변수에만 보관, 채팅·코드 금지 |
| 회사 팀 소유로 인한 지속성 | 중 | 중 | 계정 변경·퇴사 시 이전 계획 문서화 |

## 11. 역할

| 사람 | 할 일 |
|---|---|
| 사용자 | Supabase 접속 주소를 Vercel/로컬 환경변수에 입력, 전환·이전 날짜 확정, 공지 올리기, 점검표 눈 확인, Vercel 팀 권한·결제 |
| 작업자(Claude) | 어댑터·이전·검증·역복사 스크립트, 점검 모드, 테스트, 리허설 실행, 배포, 점검표 진행·기록 |

## 12. 실행 전 결정할 것

1. 사용량 초기화일, 그 직후 대회 일정(전환 후보 평일 새벽 2~3개 날짜).
2. 점검 허용 시간대(예: 00:30~01:30).
3. Supabase 프로젝트: 이름, 비용 감수 여부(`MICRO` 월 약 $10 추가).
4. Vercel: 주소 유지 방식(Transfer / 복제 + 도메인), 내 도메인 구입 여부.
5. 백업 파일 보관 위치(2곳 이상).
6. 롤백 판단자와 연락 방법.

## 13. 하지 않을 것

- 대회 주간·대회 당일 전환.
- DB와 호스팅을 같은 날 함께 전환.
- 회사 프로젝트의 `service_role` 키 사용, Data API 공개.
- 전환 직후 Upstash 삭제.
- 점검표 없이 "되는 것 같다"로 마무리.

## 14. 진행 기록

### 2026-10-18 · P1 개발 + P2 리허설 (운영에는 아무 영향 없음, 배포 안 함)

**만든 것**
- `src/lib/kv/pg-requester.ts`: Postgres 어댑터. Upstash 클라이언트(`new Redis(요청기)`)에 꽂는 방식이라 값 변환·파이프라인 동작은 지금과 완전히 같다. 앱이 쓰는 명령 전부 + 이전 도구용 `scan/type/pttl/dbsize` 지원.
- `src/lib/kv/client.ts`: `DATA_BACKEND=postgres` 이면 Postgres, 아니면 Upstash(기본, 지금과 같음). `hub.ts`·`db.ts`·`event.ts` 의 클라이언트 3곳을 여기로 통일.
- `scripts/kv/backup.mjs` (백업) · `import.mjs` (가져오기) · `verify.mjs` (원본·대상 전부 비교) · `lib.mjs`.
- `tests/pg/adapter.test.mjs`: 어댑터 점검 14개 (`npm run test:pg`, 로컬 Postgres 필요).
- `npm run test-day:pg`: 로컬 Postgres 위에서 앱을 띄우는 테스트 모드.

**결과**
- 어댑터 점검 14/14 통과 (특수문자, 만료, NX, 파이프라인 800개 58ms, 멀티 롤백, 동시 incr 50번 정확히 50, 같은 순간 명령 묶기와 오류 격리).
- **운영 데이터 읽기 전용 복사 → 로컬 Postgres 가져오기 → 비교: 196개 키 전부 일치** (해시 182, 문자열 14).
- 실제 데이터 복사본 위에서 앱 주요 화면 18곳 모두 200, 서버 오류 0.
- 쓰기 흐름(출석 체크, 코스 변경, 포인트)이 Postgres 에 제대로 저장됨.

**발견한 것 → 계획 반영**
1. **미들웨어는 엣지에서 돌아 DB 에 직접 접속할 수 없다.** 빙고 공개 확인(`/bingo`)을 `/api/event/visible` 호출로 바꿨다. 기본(Redis) 상태에서도 이 경로가 쓰이므로, **배포 후 `/bingo` 접근을 점검표에 추가**한다. (8장)
2. **왕복 횟수가 속도를 좌우한다.** 같은 순간에 나가는 명령을 한 번에 묶도록 해서 화면당 왕복을 14~24번 → 4~9번으로 줄였다. 그래도 서버가 멀면 느리다:
   - Vercel 함수 지역(기본 미국 동부)과 Supabase(서울)가 멀면 왕복 1번에 약 0.15~0.2초 → 화면 하나에 1~2초.
   - **전환 전 필수: Vercel 함수 지역을 서울(`icn1`) 또는 도쿄(`hnd1`)로 바꾸고 응답 시간을 잰다.** (Hobby 에서 지역 변경이 되는지는 확인 필요. 회사 Pro 팀으로 옮기면 가능.)
3. 대회 목록 캐시 키에 저장소 이름을 넣어, 전환 직후 옛 저장소 데이터를 보여 주지 않게 했다.
4. `/races` 화면 HTML 이 **약 1.6MB**(대회 37개 전부 그림). 전환과 별개로, 지난 대회를 접어 두는 식의 경량화를 나중에 검토(데이터 전송량과 속도).
5. 운영 DB 는 현재 **문자열 14 + 해시 182**, 정렬집합·리스트 0 (뉴스 수집 기록 등은 만료되어 비어 있음). 이전 절차가 단순하다.

**다음에 할 것**
- Supabase `DATABASE_URL` 이 `.env.local` 에 들어오면: 같은 도구로 **원격 리허설**(백업→가져오기→비교)과 서울 지역 속도 측정.
- 점검 모드(`MAINTENANCE=1`, 쓰기 차단)와 전환 당일 스크립트 정리.
- 역복사(롤백용) 스크립트.

**이전 도구 사용법**
```
node scripts/kv/backup.mjs [파일]                         # 원본(Upstash) → backups/파일.json (읽기 전용)
DATABASE_URL=... node scripts/kv/import.mjs 파일 --truncate # 파일 → Postgres
DATABASE_URL=... node scripts/kv/verify.mjs                 # 원본과 대상이 같은지 전부 비교
```
`backups/` 폴더는 개인정보가 들어 있어 git 에 올라가지 않는다.
