# 12월 이벤트 「기록 챌린지」 기획서

작성일 2026-11-20 · 상태: 기획 확정 대기(운영진 검토) · 구현 계획은 이 문서 승인 후 별도 작성

## 1. 목적과 원칙

12/1~12/18 러닝 기록 챌린지(6개 부문)를 앱에서 신청부터 시상까지 운영한다. 목표는 **분쟁이 생기지 않는 것**이다.

1. **규칙은 신청 전에 확정한다.** 신청자는 규정에 동의하고(동의 시각 기록), 이후에는 오타 외에 규정을 바꾸지 않는다.
2. **판정은 가능한 한 자동으로 한다.** 8분 페이스, 일수, 합계, 순위는 시스템이 계산한다. 사람이 판단하는 부분은 캡처 검수와 장소 묶기뿐이다.
3. **모든 판정은 투명하다.** 본인 활동마다 인정/제외 사유를 보여 주고, 판정 변경은 사유와 함께 로그로 남긴다.
4. **모든 기록은 사진 인증이 필요하다.** 활동마다 캡처 1장이 없으면 저장되지 않는다. 부문별 추가 캡처도 필수다.

## 2. 부문과 판정 규칙

공통: 인정 활동은 **평균 페이스가 km당 8:00 이내(8:00 포함, 더 빠른 것)**여야 한다(Zone 2 부문은 면제). 평균 페이스는 입력하지 않고 거리÷시간으로 계산하며, 초 아래는 버린다(예: 8:00.8은 8:00). 느린 활동은 해당 활동 전체(거리·시간)를 제외한다. 로드·트레드밀·트랙 모두 인정한다. 하루는 활동 **시작 시각 기준 한국 날짜**다.

| # | 부문 | 순위 기준 | 추가 조건 | 추가 증빙(캡처) |
|---|---|---|---|---|
| 1 | 거리 | 인정 활동 거리 합계 | | 활동 요약 |
| 2 | 최장시간 | 인정 활동 시간 합계(기록 시간, 이동 시간 아님) | | 활동 요약 |
| 3 | 케이던스 | 10km 이상 활동 1건의 평균 케이던스 최고 | 합산 없음, 8분 규칙 적용 | 케이던스가 보이는 화면 |
| 4 | Zone 2 | 인정 활동 1건의 거리 최장 | 합산 없음, 8분 규칙 면제, **Zone 2 체류 비율 80% 이상** | 심박 구간 화면(존 번호와 비율이 보일 것) |
| 5 | 다양한 장소 | 서로 다른 장소 수 최다 | 활동 1건 40분 이상, 8분 규칙 적용, 트레드밀 제외 | 지도(경로) 화면 |
| 6 | 5km | 하루 인정 활동 거리 합이 5km 이상인 **날의 수**(연속 아님) | 하루 여러 번 나눠 뛴 합산 허용, 8분 규칙은 활동별로 적용 | 활동 요약 |

- 한 활동이 여러 부문에 동시에 해당할 수 있다(예: 12km 활동이 거리, 케이던스, Zone 2에 모두 쓰임).
- **장소 판정:** 입력은 "구 + 공원·코스명" 형식이다. 지도 캡처상 출발 지점이 서로 3km 이상 떨어져 있으면 다른 장소다. 운영진이 입력값을 하나로 묶은 **장소 정리표를 참가자에게 공개**한다.
- **동률:** 거리·시간은 소수 둘째 자리까지 비교한다. 같으면 평균 페이스가 빠른 사람, 그래도 같으면 마지막 인정 기록의 시작 시각이 빠른 사람이 이긴다. 세 기준이 모두 같으면 공동 순위로 표시하고 운영진이 별도로 정한다. 앞 부문에 이런 동점이 있으면 그 뒤 부문의 수상은 동점 정리 전까지 "앞 부문 동점 정리 후 확정"으로 잠정 표시한다.

## 3. 수상

- 1등만 시상한다. **1인 1상**이다. 부문 확정 순서는 거리 → 시간 → 케이던스 → Zone 2 → 장소 → 5km다. 앞 부문 수상자는 뒤 부문에서 빠지고 차순위가 올라온다.
- 상품은 부문에 고정하지 않고 **확정 순서대로 수상자가 고른다.** 상품은 부문 수(6개)만큼 필요하다. 현재 예정은 넥워머, 카프슬리브, 오스무브 모자, 데카르트 장갑이고 **2개를 추가해야 한다.** 목록에는 "예정, 변경될 수 있음"을 표기한다.
- 상품은 본인만 수령한다. 포기해도 자동으로 차순위에게 넘기지 않는다. 순위와 상품의 양도는 없다.

## 4. 신청과 회비

- 신청하고 회비 5,000원 입금이 확인된 사람만 참가한다.
- 입금 확인 전에도 기록은 올릴 수 있지만, 순위와 수상에는 입금이 확인된 사람만 포함한다. 신청 취소는 신청 기간 안에만 가능하고 환불은 없다.
- 신청할 때 규정 동의를 체크한다(동의 시각 기록). 입금 확인은 운영진이 처리하며, 확인되면 참가가 확정된다.
- **회비는 환불하지 않는다.** 신청 취소와 중도 포기 모두 해당하며, 동의 문구와 규정에 명시한다. (운영진이 이벤트를 열지 못하는 경우의 환불은 §10 확인 사항)
- 신청 마감은 11/30 23:59다. 모인 회비 총액과 상품 구입 내역을 이벤트 화면에 공개한다.
- 운영진도 참가할 수 있다. 순위는 자동 계산하고, 운영진 본인 기록은 다른 운영진이 검수한다.

## 6. 참가자 화면

1. **규정 화면:** 이벤트 탭 상단에 규정을 짧고 친근하게 4개 영역(기록·부문·수상·참가)으로 묶어 고정한다. 신청 전에 읽고 동의한다.
2. **기록 올리기:** 날짜, 시작 시각, 거리, 시간, 종류(로드/트레드밀/트랙), 활동 캡처 필수. 부문에 해당하면 평균 케이던스, 평균 심박, 장소를 입력하고 추가 캡처를 올린다. 캡처가 없으면 저장이 막힌다.
3. **내 활동 목록:** 활동마다 평균 페이스, 인정/제외 여부와 사유, 검수 상태(검수 전, 인정, 반려와 사유)를 보여 준다. 기간 중에는 수정과 삭제가 가능하다(12/20까지, 이력 보존).
4. **부문별 순위:** 잠정 순위를 보여 준다(검수 전 기록은 "검수 전" 표시). 장소 정리표(같은 장소로 묶은 입력과 건수만, 닉네임·캡처 없이)와 회비 사용 내역도 이 화면에서 본다. 기록 기간 중에는 검수 전 기록을 포함한 잠정 순위, 12/21부터는 검수 완료 기록 기준 순위를 보여 준다.
5. **이의 제기:** 12/22까지 활동 단위로 사유와 함께 접수한다.

## 7. 운영진 화면

- 입금 확인 목록, 참가 확정 처리
- 기록 검수 큐: 캡처 확인 후 승인 또는 반려(사유 필수). **각 부문 상위 3위 후보는 캡처를 전수 확인**하고, 나머지는 표본 검수한다.
- 장소 정리표 관리(입력값을 장소로 묶기, 묶음 변경 이력)
- 이의 제기 처리와 결과 사유 공개
- 최종 확정, 1인 1상 조정, 상품 선택 순서 안내
- 모든 판정 변경은 시각, 처리자, 사유를 로그로 남긴다. 운영진 본인 기록은 본인이 검수할 수 없다.

## 8. 기존 앱과의 연결(구현 시 방향)

- 이벤트 블록(`src/lib/event-blocks.ts`)에 "챌린지" 종류를 추가한다. 신청 기간(11/24~)이 11월 빙고 기간과 겹쳐 본문 블록이 가려지므로, 챌린지는 `/event/challenge` 전용 경로로 열고 이벤트 탭 위에 배너로 연결한다. 12/1 이후 본문 블록이 챌린지이면 이벤트 탭에서 바로 보인다.
- 참가 명단은 빙고용 명단과 분리한다(블록별 키). 회비 입금 확인과 규정 동의 시각을 항목에 함께 저장한다.
- 이미지는 공구 시안 이미지처럼 base64를 KV에 저장하는 방식을 따르고 크기 제한을 둔다. 활동 하나에 캡처가 여러 장 붙으므로 용량은 구현 계획에서 점검한다.
- 이번 이벤트에는 가민 CSV 업로드를 쓰지 않는다. 증빙은 전부 캡처다.
- 이벤트 기간은 빙고와 달리 챌린지 블록이 자체 일정(신청 마감, 기록 기간, 업로드 마감 등)을 가진다.

## 9. 범위 밖

가민 CSV 자동 판정, 외부 서비스 연동, 실시간 푸시 알림(필요하면 기존 알림 재사용을 별도 검토), 환불 처리.

## 10. 확인이 필요한 사항

- 추가 상품 2개의 종류와 예산
- 운영진 사정으로 이벤트가 취소될 때의 환불 여부(기본안: 전액 환불)
- 케이던스 부문의 "10k 이상"은 활동 1건의 거리 10km 이상으로 해석했다.
- 신청 기간의 시작일(기본안 11/24)

## 11. 운영진 테스트 모드

크루원에게 보이지 않게 라이브 사이트에서 챌린지 전 과정을 시험해 보고, 끝나면 테스트 데이터를 지우기 위한 기능이다.

- 설정: 챌린지 설정에 `testMode`(켬/끔)와 `testPhase`(고정할 단계, 빈 값이면 날짜대로)를 둔다. 일반 설정 저장 폼은 이 두 값을 건드리지 않는다. 켜고 끌 때는 비밀번호 확인 없이 처리 기록(`test-mode`)만 남긴다.
- 노출: 테스트 모드인 챌린지는 운영진(실제 운영진, 크루 보기 중에도)에게만 보인다. 이때는 신청 시작 전후 같은 날짜 범위를 보지 않고 언제든 보인다. 크루원에게는 챌린지가 없는 것처럼 동작한다(배너 없음, `/event/challenge`는 이벤트 탭으로 이동, 이벤트 탭 본문에도 나오지 않음). 닉네임 변경 보호 검사는 테스트 모드 챌린지를 무시한다.
- 단계: `testPhase`가 있으면 모든 화면과 참가자 동작(신청·기록·이의 제기)이 날짜가 아니라 그 단계를 따른다.
- 기록 기간: 테스트 모드에서는 기록 인정 기간을 2000-01-01 ~ 2099-12-31로 넓혀 판정·입력 검증·순위·시상에 쓴다(오늘 날짜의 활동으로도 시험할 수 있다). 일정 표시와 단계 판단에는 설정된 날짜를 그대로 쓴다. 미래 시각의 활동은 여전히 막는다.
- 검수: 테스트 모드에서는 운영진이 본인 기록도 승인·반려할 수 있다.
- 시상: 종료 단계에서 최종 확정 시각 이전이어도 테스트 모드에서는 시상 결과를 보여 준다.
- 초기화: 테스트 모드가 켜져 있을 때만 ‘테스트 데이터 모두 지우기’(비밀번호 확인)를 쓸 수 있다. 신청자·기록(캡처)·장소 정리표·이의 제기·처리 기록을 지우고 “테스트 데이터 초기화” 처리 기록 한 줄을 남긴다. 챌린지 블록과 설정은 그대로 둔다.
- 화면 표시: 참가자 화면 위에 “🧪 테스트 모드 · 운영진에게만 보여요 · 단계: …” 띠를, 운영진 관리 화면에 “테스트 모드 켜짐 — 운영진에게만 보여요” 문구를 보인다.
